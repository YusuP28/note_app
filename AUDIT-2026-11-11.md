## 🔴 KRITIS

### K1 — Backup plaintext ditulis otomatis ke storage bersama, tiap launch
`lib/services/backup_service.dart:19,44-48` · `lib/main.dart:31`

```dart
static const String _publicBackupPath = '/sdcard/Download/note_app';
// main.dart:31
await BackupService().autoBackup();
```

`autoBackup()` dipanggil **tanpa syarat apa pun** di `main()`. `_resolveBaseDir()` (`backup_service.dart:55-72`) selalu mencoba `/sdcard/Download/note_app` DULUAN, dan fallback ke app-documents hanya kalau penulisan gagal. Isi `data.json` memuat kolom `content` + `plain_text` seluruh catatan, **tanpa enkripsi sama sekali** (`grep -i encrypt/cipher` di `backup_service.dart` + `google_drive_service.dart` → 0 hasil).

Dampak: setiap app launch menulis salinan lengkap semua catatan ke storage yang dibaca app lain / ADB pull. Ini membatalkan seluruh nilai fitur "lock".

**Fix:** defaultkan ke app-private dir (`getApplicationDocumentsDirectory()`), jadikan `/sdcard/Download` sebagai opsi **eksplisit** yang dipilih user, danenkripsi payload dengan AES-GCM (key di Android Keystore).

### K2 — "Kunci Catatan" hanya kosmetik; plaintext tetap di SQLite
`lib/services/database_service.dart:65-87` · `lib/widgets/note_card.dart:29` · `lib/services/backup_service.dart:97-109`

Database memakai `sqflite` biasa (bukan `sqflite_sqlcipher`). Tabel `notes` menyimpan `content` dan `plain_text` untuk SEMUA catatan, termasuk yang `isLocked == 1`. Yang dilakukan lock hanya **masking di layer UI** (`note_card.dart:29`). Backup juga menyalin `plain_text` tanpa kecuali.

Dampak: siapa pun yang punya akses root/ADB, atau aplikasi restore, bisa membaca catatan terkunci.

**Fix:** `sqflite_sqlcipher` dengan key di Android Keystore, atau minimal hapus `plain_text` untuk catatan locked danenskripsi kolom `content` per-catatan.

### K3 — Upload plaintext ke Google Drive
`lib/services/google_drive_service.dart:123-163` · `lib/services/auto_backup_service.dart:26-46` · `lib/main.dart:43-45`

```dart
final api = await _getDriveApi();
final list = await api.files.list(spaces: 'appDataFolder', q: "name='$fileName'");
```

Payload ZIP **plaintext** masuk ke `appDataFolder` Google. Consent ada (toggle `autoBackupDays`, default **0 = off** — `settings_provider.dart:34`), jadi tidak otomatis aktif. Namun `main.dart:43` memanggil `gd.signInSilently()` **tanpa syarat** di setiap launch — itu adalah koneksi ke pihak ketiga tanpa persetujuan eksplisit.

**Fix:** enkripsi payload sebelum upload (kunci dari Keystore), dan hapus `signInSilently()` unconditional dari `main()` — cukup panggil saat user buka halaman Drive.

## 🟠 TINGGI

### H1 — Backup code 6 digit: tanpa throttle, dan reset lockout
`lib/services/lock_service.dart:141-173`

`verifyBackupCode()` **tidak pernah** membaca `_kLockUntil` dan tidak menaikkan `_kFailCount` — berbeda total dari `verifyPin()` yang melakukan keduanya (`:118-135`). 10⁶ kombinasi dicoba tanpa batasan. Lebih buruk: `resetWithBackupCode()` → `setPin()` yang me-**reset** `_kFailCount = 0` dan menghapus `_kLockUntil` (`:63-64`).

**Fix:** samakan dengan `verifyPin()` — cek lockout, naikkan fail count, dan **invalidasi permanen** backup code setelah dipakai (hapus hash-nya, jangan buat baru diam-diam).

### H2 — Path traversal saat restore backup
`lib/services/backup_service.dart:436-447` (`_toAbsoluteMedia`)

```dart
if (normalized.startsWith('$_attachmentsFolder/')) {
  return p.join(attachmentsRoot, normalized.substring(_attachmentsFolder.length + 1));
}
```

`path.join` menormalisasi `../`, jadi nilai `attachments/../../../../data/data/...` keluar dari sandbox. Nilai ini berasal dari JSON dalam file backup —也就是 **file yang dikontrol penyerang**. `_toRelativeMedia` sudah benar (`:426-427` pakai `p.isWithin`), tapi sisi absolutnya tidak.

Dampak: file arbitrary bisa dibaca (`local_image_embed.dart:19`) atau dihapus (`attachment_service.dart:77-84`).

**Fix:** setelah `p.join`, wajib validasi `p.isWithin(attachmentsRoot, result)`; kalau di luar → tolak / salin ke lokasi aman.

### H3 — Rilis ditandatangani dengan debug key
`android/app/build.gradle:80-85`

```groovy
signingConfig signingConfigs.release
} else {
    signingConfig signingConfigs.debug
    println "[!] Release keystore tidak ditemukan — pakai DEBUG key"
}
```

APK publik bisa di-*re-sign* oleh siapa pun, sehingga update bisa dipalsukan.

**Fix:** `throw new GradleException(...)` bila keystore absent di mode release. Secret sudah tersedia di CI (`KEYSTORE_BASE64`).

### H4 — Draft catatan plaintext di SharedPreferences
`lib/screens/notes/edit_screen.dart:190-206, 241-245`

`draft_<id>_title` / `draft_<id>_content` disimpan plaintext di XML prefs. Sudah ada guard `_working.isLocked` (`:191`) — bagus — tapi catatan biasa tetap plaintext di disk.

**Fix:** minimal hapus draft saat app background; idealnya enkripsi.

### Temuan Baru Saat Implementasi

1. **Envelope backup tidak bisa dibuka** — format header `NBNOTE2` bentrok dengan magic internal `BackupCrypto` (`NBNOTE1`). Tertangkap test.
2. **`encryptRow` bisa salah encrypt** — API menerima flag `isLocked` terpisah dari row, jadi caller bisa salah pass dan mengencrypt catatan yang tidak terkunci (atau sebaliknya). Diperbaiki: status lock dibaca dari kolom `is_locked`, satu sumber kebenaran.
3. **Build debug ikut gagal** — `throw` di dalam block `buildTypes` dievaluasi saat **konfigurasi** Gradle, bukan hanya saat build type dipakai. Tertangkap CI run #42922725454.
4. **5 warning lama memblokir CI** — `flutter analyze` exit code 1 meski 0 error. Dibersihkan (import & variabel tak terpakai).
